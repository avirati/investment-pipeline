# Golden memos

TESTING §7: one golden analysis in, one golden memo out, both committed, so a
change to how a memo reads is reviewed as a diff in a markdown file.

These are **not** fixtures. Nothing here was captured from the network —
`tests/fixtures/` is for that, and everything in it is recorded in
`capture.json`. These are artifacts: two analyses this pipeline could produce,
and the memos rendered from them.

| File | What it is |
| --- | --- |
| `analysis.golden.json` · `evidence.golden.json` | **Input.** A Watch: three fact sections, a low-confidence statement, a partial status, an upgrade trigger three points from a meeting. |
| `analysis.thin.json` · `evidence.thin.json` | **Input.** A Pass forced by two disqualifiers: a Risks section, two uncovered dimensions, a site that did not resolve. |
| `memo.golden.md` · `memo.thin.md` | **Output.** Regenerated by `pnpm golden`. |

The two analyses were produced by running the real `scoreCandidate` and
`deriveMemoFields` over hand-written facts and signals, so their scores, bands,
sections and triggers are the pipeline's own arithmetic rather than numbers
somebody typed. They are frozen inputs now: edit them only deliberately, and
expect the memo diff to be the reason you are doing it.

## Changing the template

```bash
pnpm golden          # rewrite the two snapshots
pnpm golden --check  # fail if they are stale, without writing
```

Then read the diff. A template change that makes a memo worse is visible here
and nowhere else — `pnpm test` will tell you the snapshot moved, not whether it
moved in the right direction.

## What they do not cover

The companies are invented. Whether the rubric's bands are *right*, and whether
a partner can act on these memos, are questions no snapshot answers — there is
no eval harness in v1 (SCOPE), and TICKET-0028's committed run against real
companies is where that gets looked at.
